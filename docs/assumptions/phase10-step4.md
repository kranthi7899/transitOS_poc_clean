# Phase 10 Step 4 assumptions (A105-A114)

Reserved block A105-A114 (plan: "Reserved id blocks"). Kept here, not in `docs/ASSUMPTIONS.md`, so parallel builders
never collide; the supervisor merges. Every row is tagged in the code with its id. All products are SIMULATED and
generic: the pending-repair vocabulary was read from public descriptions of shop systems (research digest section 5)
and copies no product's API. Every number here is ASSUMED unless it says otherwise.

## Decisions taken without the owner

- The canonical WorkOrder for a pending repair keeps the request id (A106) rather than switching to the converted work
  order's id: one effect per idempotency key, and compensation works whether or not the foreman got there first.
- `human_wo_exists_pending` is the RACE variant (a person opens a work order after our request, before the foreman
  converts it); the "person first, before the trigger" case in pending mode is a test
  (`test_pending_mode_with_a_human_work_order_before_the_trigger_creates_no_request`).
- The local-time knob turns on all three wire changes at once in scenarios (maintenance local, workforce CSV local,
  telematics epoch ms).
