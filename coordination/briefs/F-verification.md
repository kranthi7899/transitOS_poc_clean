# Track F — Verification (src/transitos/verification/, tests/e2e/)
Build the verification harness that proves Level 2, runnable once tracks merge, and prepare it now against interfaces: (1) `verification/scenarios.py`: ~20 scenario definitions as data (trigger event, seeded world tweaks, chaos switches, expected outcome class: plan-valid / escalate-no-safe-option / etc.) covering: severe fault w/ spare, PM overdue, DVIR defect, last spare, wheelchair/lift need mismatch, operator hours exhausted, unqualified operator, no feasible spare, duplicate trigger, trigger for vehicle with active run, human WO exists, unresolved vehicle ID, product down on read. (2) `verification/invariants.py`: pure checkers over a run's final state + audit (hard limits satisfied in 100%; idempotent writes: <=1 WO per run; rider alert only after all other steps succeeded; every write has audit record; no write occurred before approval; no write after kill switch). (3) `tests/e2e/test_level2.py`: the 12 acceptance tests from the spec written as pytest tests against a `World` fixture interface (`tests/e2e/world.py` with a Protocol; skip with a clear reason until the integration lead provides the real World). Implement a `FakeWorld` for now so the invariants themselves are tested. (4) `verification/report.py`: runs scenarios, prints a table (scenario, outcome, invariants pass/fail) and writes JSON. 
Tests: each invariant has a passing and a deliberately violating case. Do not modify other tracks' code.
