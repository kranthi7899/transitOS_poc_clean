# Track E — Panel and ops (src/transitos/panel/, tests/panel/)
FastAPI + htmx (server-rendered Jinja-free: plain f-string/templates acceptable; phone-friendly responsive). Endpoints per design: `GET /pending?agency=`, `GET /runs/{run_id}` (plan, reasoning, facts, history, audit trail), `POST /runs/{run_id}/decision` {decision, plan_version, edits?, user} -> 409 if plan_version stale, `POST /defects` (human fault report -> enqueue a DefectReported/VehicleFaultDetected(source=human) event via an injected `EventSink`), `GET /unresolved`, `POST /crosswalk` (fix mapping -> calls Crosswalk.resolve and republishes returned events), `POST /killswitch {agency,on}`, plus HTML pages: pending list, run detail with Approve/Reject/Edit, unresolved list, kill switch toggle, simple event/audit timeline. Depend on injected interfaces only: `RunGateway` (list_pending, get_run, submit_decision), `Crosswalk`, `EventSink`, `AuditReader`, `KillSwitchStore` — define these Protocols in `panel/ports.py` and ship in-memory fakes in `panel/fakes.py`. The real wiring happens at integration (lead will do it); do not import other tracks' code.
Tests: stale plan_version rejected; decision resumes via gateway exactly once (double submit idempotent); unresolved fix republishes parked events; kill switch toggles; HTML pages render for a fake pending plan; defect report produces an event with source=human.
