# D-1: operator qualification fields and hours limits (additive, v1.2)

Phase 10 Step 1 (D-A, D-B, Amendment A). The current `Operator.qualifications: list[str]` mixes licence codes and
vehicle types, which is why the agency-042 seed cannot complete a run (A26).

Add to `contracts/objects.py::Operator` (all optional; existing fields stay, legacy `qualifications` is ignored by the
new check whenever the new fields are set):
- `licence_class: Literal["A","B","C"] | None = None`
- `endorsements: list[str] = []` (for example `"P"` passenger)
- `trained_vehicle_types: list[str] = []` (for example `"standard"`, `"articulated"`)
- `training_valid_to: dict[str, datetime] = {}` (key = endorsement code, trained type, or `"lift"`)
- `medical_valid_to: datetime | None = None`
- `last_duty_end: datetime | None = None`
- `duty_start_today: datetime | None = None`

Add to `contracts/policy.py::Limits`:
- `max_operator_hours_week: float = 70.0` (8-day window, 49 CFR 395.5 default; ASSUMED)
- `min_rest_hours: float = 8.0`
- `max_spread_hours: float = 15.0`

Missing data is never a violation (Amendment A): the clearance module reports `unverifiable` or `not_evaluated`.
Affects: C (clearance, adapters), D (limits, graph), A (seed, workforce mock), F (golden table).
